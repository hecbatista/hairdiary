# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project overview

Hair Diary is an iOS app (React Native + Expo + TypeScript) for anyone caring for their hair. Users log hair care entries on a calendar (washes, haircuts, masks, treatments, Good Hair Days) and manage a profile. The backend is Supabase (Auth, Postgres with RLS, Storage).

It is a portfolio project: favor clean, well-documented, tested code over quick hacks. The roadmap lives in the README and is tracked as issues on the [Hair Diary Roadmap](https://github.com/users/hecbatista/projects/1) project board.

## Commands

```bash
npm start            # Expo dev server (press i for iOS simulator)
npm run ios          # Start directly on the iOS simulator
npx tsc --noEmit     # Typecheck (strict mode)
npm run lint         # ESLint (expo config + TypeScript rules + Prettier)
npm run lint:fix     # ESLint with autofix
npm run format       # Format everything with Prettier
npm run format:check # Check formatting without writing
npm test             # Jest (jest-expo preset + React Native Testing Library)
npm run test:watch   # Jest in watch mode
npx jest <path>      # Run one test file or folder

npx supabase start                    # Start the local Supabase stack (Docker); applies migrations + seed
npx supabase status                   # Print local URLs and keys (API URL, anon/publishable key, Studio)
npx supabase stop                     # Stop the local stack (keeps data)
npx supabase migration new <name>     # Create supabase/migrations/<timestamp>_<name>.sql
npx supabase db reset                 # Rebuild the local database from all migrations + seed.sql
npm run gen:types                     # Regenerate lib/database.types.ts from the local database schema

infra/azure/deploy.sh                 # Create/update the prod VM on Azure and (re)start Supabase on it
infra/azure/push-migrations.sh        # Apply supabase/migrations/ to prod (--dry-run to preview)
```

CI (`.github/workflows/ci.yml`, GitHub Actions) runs on every PR and every push to `main`: `npm ci`, then
`npx tsc --noEmit`, `npm run lint`, `npm run format:check` and `npm test`, on Node 22. It uses no secrets, `.env`
or Supabase stack. Run the same four commands before pushing.

## Architecture

```
App.tsx              # Font loading, splash screen, GluestackUIProvider, native stack navigator
screens/             # One file per screen (Login, Home, AddEntry, Profile)
components/          # Shared UI (HeaderGradient, ScreenHeader)
components/form/     # Form wrapper, shared formStyles, and form_fields/ inputs
components/ui/       # gluestack-ui components, added by its CLI (only gluestack-ui-provider so far)
global.css           # Theme tokens (colors, fonts, type scale, spacing, radius) + Tailwind imports
navigation/          # RootStackParamList and RootStackScreenProps (typed routes)
lib/                 # Supabase client + data-access functions (the only place that talks to Supabase, except auth in LoginScreen)
type.ts              # App-level types (Entry, EntryType, ENTRY_TYPES, Profile)
colors.ts            # Colors: hex copies of the global.css color tokens, for non-className code
utils/               # Pure helpers (date formatting, today's ISO date)
**/__tests__/        # Jest tests next to the code they cover (<File>.test.ts(x))
lib/__mocks__/       # Manual Jest mock of the Supabase client (lib/supabase.ts)
test/                # Jest support, wired up in jest.config.js: timeZoneEnvironment.js (pinned TZ +
                     # setTimeZone()), globals.d.ts (its type), vectorIconMock.tsx (icon stub),
                     # styleMock.js (CSS imports), setupWindowScreen.js (window.screen for react-aria)
metro.config.js      # withNativewind: compiles global.css, adds className to React Native components
babel.config.js      # Expo's preset; tests also get nativewind/babel (see Styling)
postcss.config.mjs   # Tailwind CSS v4 PostCSS plugin
nativewind-env.d.ts  # className types; regenerated by Metro, commit it as is
supabase/            # Supabase CLI project: config.toml, migrations/, seed.sql
infra/azure/         # Prod: self-hosted Supabase on an Azure VM (deploy, bootstrap, backup scripts)
.github/workflows/   # CI (ci.yml): typecheck, lint, format check, tests on PRs and pushes to main
storage/             # Legacy AsyncStorage profile cache, superseded by lib/supabaseProfile.ts
```

**Navigation:** a single native stack in `App.tsx` with `headerShown: false`. Routes: `Login`, `Home`, `AddEntry` (param `date: "YYYY-MM-DD"`), `Profile`. Screens draw their own header with `HeaderGradient` + `ScreenHeader`. Routes and their params are declared in `RootStackParamList` (`navigation/types.ts`), which also types `useNavigation()` globally. Screens type their props as `RootStackScreenProps<"RouteName">`; components that receive `navigation` use `NavigationProp<RootStackParamList>`. A new route needs an entry in `RootStackParamList`.

**Data flow:** screens call async functions in `lib/`. HomeScreen reloads entries and the profile in `useFocusEffect`, so returning from AddEntry or Profile refreshes data automatically.

## Supabase

- Client: `lib/supabase.ts`, configured from `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` in `.env`. It throws on startup if either is missing. Never commit `.env`, never read or print its contents, and never put a service-role key in the app.
- Environment: required keys are listed in `.env.example`. Add any new variable there, and to the README's Environment setup section, in the same PR. Access variables statically (`process.env.EXPO_PUBLIC_X`) so Expo can inline them.
- Dev is the local Supabase stack (Supabase CLI + Docker, see Commands), used by `.env` and the `development` EAS build (simulator). Prod is self-hosted Supabase on an Azure for Students VM (`infra/azure/`, see its README), used by the `preview` and `production` builds. Each profile in `eas.json` reads its variables from the matching EAS environment, not from `.env`. Schema changes go in migrations so both backends stay in sync; apply them to prod with `infra/azure/push-migrations.sh`.
- Prod runs a trimmed stack on a 1 GB VM: Postgres, Auth, PostgREST, Storage, the Envoy gateway and Caddy (HTTPS). Realtime, Edge Functions, Supavisor and imgproxy are off, so a feature that needs one of them (e.g. Edge Functions for #33) also needs a bigger VM. There is no SMTP yet: prod auto-confirms email sign ups and can't send auth emails. Prod secrets live only in `~/supabase/.env` on the VM; never copy them into the repo.
- Types: `lib/database.types.ts` is generated from the local database by `npm run gen:types` (`supabase gen types typescript`, then Prettier). Never edit it by hand. After adding or changing a migration, run `npx supabase db reset` then `npm run gen:types`, and commit the regenerated file with the migration. The client in `lib/supabase.ts` is `createClient<Database>`, so table names, columns and row shapes are type checked.
- Schema lives in `supabase/migrations/` (Supabase CLI, imperative migrations). The local stack is built from it; never change a database by hand without a migration. Create files with `npx supabase migration new <name>` (don't invent timestamps), don't edit migrations that are already on `main`, and verify with `npx supabase db reset`.
- Tables (quoted, capitalized names, matching the app's `.from("Entries")` / `.from("Users")`):
  - `Entries`: `entry_id` (uuid), `user_id`, `date` (`date`, returned as YYYY-MM-DD), `entry_type` (text with a check constraint listing `ENTRY_TYPES`; adding a type needs a migration), `notes`, `created_at`
  - `Users`: `user_id`, `email`, `hair_journey`, `profile_picture`, `created_at`. One row per auth user, inserted by the `on_auth_user_created` trigger (`private.handle_new_user()`), never by the app. Users can only update `hair_journey` and `profile_picture` (column-level grant).
- Storage bucket: `profile_picture` (public, images up to 10 MiB), with files at `{user_id}/{user_id}-{timestamp}.{ext}`. Policies allow each user to read and write only their own `{user_id}/` folder.
- Every query is scoped to the current user (`.eq("user_id", user.id)`), and RLS enforces ownership server side. New tables are not exposed to the Data API automatically (`auto_expose_new_tables = false` in `config.toml`, matching hosted projects since Oct 30, 2026), so every new table's migration needs explicit `grant`s to `authenticated` (and `service_role`), `enable row level security`, and owner policies using `(select auth.uid()) = user_id` with `to authenticated`. Grant `anon` nothing unless a feature is truly public.
- Local seed (`supabase/seed.sql`): test account `test@hairdiary.test` / `password123` with a profile and a few entries.
- The auth session is not persisted yet (no AsyncStorage `auth.storage` configured; see #13).

### `lib/` function pattern

Follow the existing functions in `lib/supabaseEntries.ts`:
1. JSDoc with `@param`, `@returns` and `@throws`.
2. Get the user with `supabase.auth.getUser()` and throw `new Error("No user logged in!")` if there is none.
3. Query with the user's id and throw any Supabase `error`.
4. Map snake_case database rows (`entry_id`, `entry_type`) to the camelCase app types in `type.ts` (`id`, `type`). Use the generated helpers from `lib/database.types.ts` for database shapes (`Tables<"Entries">` for rows, `TablesInsert<"Entries">` / `TablesUpdate<"Entries">` for writes) instead of hand-written interfaces, and keep the mapping in one helper per table (e.g. `toEntry`).
5. Let errors propagate. The screen decides how to show them.

## Code conventions

- TypeScript strict mode. Function components with default exports, one component per file, file name matching the component.
- 4-space indentation (2 in JSON), double quotes, semicolons, trailing commas, 100-character lines. Prettier (`.prettierrc.json`) enforces this and runs as an ESLint rule (`eslint.config.js`), so run `npm run format` or `npm run lint:fix` instead of fixing style by hand. Lint must pass with no errors or warnings.
- Styles: `StyleSheet.create` in the same file (until #48 moves the conventions to gluestack). Use `Colors` from `colors.ts` rather than new hex values where a palette color fits. Fonts are `Poppins-Regular`, `Poppins-Medium`, `Poppins-SemiBold` and `Poppins-Bold` (set `fontFamily`, not `fontWeight`).
- Screen layout: root `View` with `flex: 1`, `backgroundColor: Colors.background`, `paddingTop: 75`, then `<HeaderGradient/>` and either `<ScreenHeader title=... navigation=.../>` or a custom header row.
- Forms: wrap fields in `<Form buttonText=... handleSave=...>` and use the inputs in `components/form/form_fields/` (`ShortText`, `LongText`, `Dropdown`, which takes its `options` as a prop). Shared input styles live in `components/form/FormStyle.tsx` (`formStyles`). Add new reusable inputs there instead of styling inputs per screen.
- Dates are `"YYYY-MM-DD"` strings throughout. Use `todayISO()` and `formatDateLong()` from `utils/`.
- Add JSDoc to exported functions and components, matching the existing style.
- Prefer small, focused changes that match the surrounding code. Don't reformat unrelated code.

## Styling: gluestack-ui and NativeWind

gluestack-ui v5 is installed on NativeWind v5 (Tailwind CSS v4), but screens and form components still use `StyleSheet` until they are migrated (#50, #51).

- Theme: `global.css` is the source of truth (Tailwind v4 is CSS-first, so there is no `tailwind.config.js`). Semantic colors are `"R G B"` triplets in `:root`, mapped to utilities in `@theme inline` (`bg-secondary`, `text-muted-foreground`, `bg-backdrop/50`). Fonts are one family per Poppins weight (`font-poppins`, `font-poppins-medium`, `font-poppins-semibold`, `font-poppins-bold`), because React Native picks a face by family, not by `font-weight`. The type scale uses Apple's text style names for the sizes the app uses (`text-footnote` 14, `text-body` 16, `text-headline` 18, `text-title-3` 20, `text-title-2` 24, `text-title-1` 28, `text-large-title` 32, `text-display` 48). Spacing is Tailwind's 4px scale, and radii are `rounded-control` (12) and `rounded-panel` (16). Light only: dark values come with #52.
- Line heights in `global.css` must be unitless ratios (`calc(28 / 20)`). react-native-css treats a px line height as a multiplier, so `28px` renders as 560.
- `colors.ts` keeps hex copies of the color tokens for code that can't take a `className` (`react-native-calendars`, `expo-linear-gradient`, `StyleSheet` screens). Change a color in both files: `__tests__/colors.test.ts` fails if they drift.
- `GluestackUIProvider` (`components/ui/gluestack-ui-provider/`) wraps the app in `App.tsx` with `mode="light"`, and hosts overlays and toasts. Add components with `npx gluestack-ui@latest add <name>`; they land in `components/ui/` and import each other through the `@/` alias (`tsconfig.json` paths; Metro reads it, Jest maps it in `jest.config.js`). Check what the CLI changes before committing: `init` wrote `mode="dark"`, a stale `tailwind.config` Babel alias, a `.npmrc` with `legacy-peer-deps`, and native versions newer than SDK 54's Expo Go.
- Runs in Expo Go, with no dev client: NativeWind v5 needs `react-native-reanimated` 4.1 and `react-native-worklets` 0.5, which Expo Go for SDK 54 bundles.
- **Preview risk.** NativeWind v5 is a prerelease. Versions are pinned exactly: `nativewind@5.0.0-preview.4` with its engine `react-native-css@3.0.7`, `tailwindcss` and `@tailwindcss/postcss` `4.1.12`, and `lightningcss` `1.30.1` through `overrides` (other versions fail to deserialize `global.css`). `overrides` also pins `react-native-css`'s `@expo/metro-config` peer to SDK 54, which npm otherwise resolves to a newer SDK's copy. Upgrade `nativewind` and `react-native-css` together as the pair the NativeWind docs name (5.0.0-rc.x needs `react-native-css` 3.1.0-rc.x and is tested on Expo SDK 57), then run the tests and check the app on the simulator. Don't add `legacy-peer-deps`: it hides real peer conflicts. `@legendapp/motion` (a gluestack base dependency, used by some animated components) is left out because its `nativewind >=4` peer rejects prereleases. A component that needs it should add an `overrides` entry for that peer.

## Testing

- Jest with the `jest-expo` preset (`jest.config.js`) and React Native Testing Library. Tests live in `__tests__/` next to the code, named `<File>.test.ts(x)`. Run `npm test` before committing; it needs no `.env` or Supabase stack.
- Test behavior, not implementation: what a function returns or throws and what it asks Supabase for, or what a component shows and reports through its props.
- `lib/` tests: call `jest.mock("../supabase")` (uses `lib/__mocks__/supabase.ts`) and read `supabase`, `mockUser` and `createQueryBuilder` with `jest.requireMock("../supabase")`. Don't import from `__mocks__` directly: that is a separate module instance from the one the code under test sees. Assert user-id scoping (`eq("user_id", ...)`), snake_case → camelCase mapping, `"No user logged in!"`, and error propagation.
- Mocks: `lib/` tests call `jest.resetAllMocks()` in `beforeEach`, so every test sets its own user and query results (a test that forgets `mockUser()` fails instead of inheriting one). Don't turn on `resetMocks` globally: it also wipes jest-expo's React Native mocks. Mock globals with `jest.spyOn(global, "fetch")` and undo them with `jest.restoreAllMocks()` in `afterEach`, rather than reassigning them.
- Time zones: every test starts in `America/Los_Angeles` (`test/timeZoneEnvironment.js`), so results don't depend on the machine. Call the `setTimeZone("Pacific/Auckland")` global to switch zones within a test; setting `process.env.TZ` in a test has no effect. Test date code in the evening in a zone behind UTC and the morning in one ahead of it, with `jest.useFakeTimers({ now })`.
- NativeWind: Jest doesn't run Metro, so `babel.config.js` adds `nativewind/babel` in the test env. It rewrites `react-native` imports to `react-native-css` components, which is what makes `className` work, as `withNativewind` does in the app. `global.css` imports resolve to `test/styleMock.js`. To assert real styles, compile `global.css` with Tailwind and register it with `registerCSS` from `react-native-css/jest` (see `components/ui/gluestack-ui-provider/__tests__/`). `jest.config.js` also transforms `nativewind`, `@gluestack-ui` and `tailwind-variants`, which ship untranspiled code.
- Component tests: query by what the user sees (`getByText`, `getByPlaceholderText`, `getByDisplayValue`) and use `fireEvent` for presses and typing. Icons render as `<View testID="icon-<name>">`.
- Upgrading Expo: run `npx expo install --check` to see the `jest-expo` / `jest` / `@types/jest` versions the SDK expects and install them with `npm install --save-dev` (`npx expo install ... -- --save-dev` puts them in `dependencies`). Keep `react-test-renderer` pinned to the exact `react` version.

## Known issues

- `HomeScreen` imports `loadProfile` from `storage/profileStage` but shadows it with a local function of the same name. The `storage/` module is unused legacy code.
- Errors are mostly only `console.error`'d with no user feedback (#13).

## Workflow

- Work is tracked as GitHub issues with a milestone per roadmap phase and labels (`feature`, `chore`, `tech-debt`, `frontend`, `backend`, `infra`, `research`). Sprints are 2-week iterations on the project board.
- Branch from `main` with names like `feat/<issue>-short-name`, `chore/<issue>-short-name` or `docs/short-name`.
- PRs target `main`, reference the issue with `Closes #N`, and are merged with merge commits.
- When a change adds tooling, commands or conventions, update this file in the same PR.

## Claude Code setup

- Project skills live in `.claude/skills/`:
  - `start-issue`: issue → branch → board status → PR that closes the issue
  - `add-screen`: new screen with the standard layout, registered in `App.tsx`
  - `add-data-function`: Supabase data-access function in `lib/`, plus schema/RLS changes
  - `add-form-field`: reusable input in `components/form/form_fields/`
- Add a skill when a workflow repeats, e.g. writing tests (see the Testing section) or writing migrations now that the Supabase CLI is set up.
- `.claude/settings.json` holds shared permissions: safe read-only commands are allowed and reading `.env` is denied. It also enables the Expo plugin. Personal overrides go in `.claude/settings.local.json`, which is git-ignored.
